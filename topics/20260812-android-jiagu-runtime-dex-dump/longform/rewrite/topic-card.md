# 选题卡　360 加固 APK 的识别、运行时 DEX 恢复与常见坑

## 核心任务

以一个真实的 Android 14 样本说明拿到加壳 APK 后怎样识别壳特征、选择动态环境、从进程内存恢复 DEX、区分业务代码与第三方依赖，并判断恢复结果是否可用。

## 目标读者

了解 APK、ADB、JADX 和 DEX 基本概念，准备动手分析加固应用的 Android 逆向研究者。

## 读者应当带走的能力

1. 用 Manifest、native 库、外层 DEX 规模和包结构判断壳接管，而不是只看 JADX 是否报错。
2. 区分“符合 360 加固家族特征”和“已经精确识别壳版本”。
3. 理解合法 DEX、壳 DEX、业务 DEX、框架 DEX 和第三方 SDK DEX的区别。
4. 准备 ABI 匹配、可以读取进程内存的 userdebug 环境，并在 dump 前触发延迟加载代码。
5. 从 `/proc/<pid>/maps` 和 `/proc/<pid>/mem` 获取候选，校验 DEX 头、边界并按内容哈希去重。
6. 用 class descriptor、Manifest 组件和反编译目录判断恢复质量。
7. 根据无 magic、重复 DEX、JADX 报错等现象继续排查。

## 内容边界

- BlockyTime 只作为样本，不讲产品复刻、UI 交互和具体业务逻辑。
- 不发布 APK、DEX、内存快照、反编译源码或本地临时脚本。
- 公开代码只处理已获授权的内存快照。
- 不把一次样本结论写成所有加固方案都适用的规律。
- 明确说明方法级解密、虚拟化、CompactDex 和 native 化需要其他路线。

## 建议结构

1. 壳接管的静态信号
2. VDEX 路线的误判
3. 动态环境与代码加载时机
4. 进程映射与内存读取
5. DEX 头部校验和去重
6. 十一份候选的分类
7. 常见失败与操作清单
