# 素材清单：有了工具站点子，别急着写代码：从需求验证到第一个用户（上）

## 论点一：写代码前先做一轮限时市场扫描

### 支撑素材

- **案例**：作者为了分享 Markdown 内容，发现现有转换工具存在不好看、带水印或订阅等不满意点，由此产生自建想法。来源：本次用户陈述。
- **市场证据**：2026-07-30 的关键词研究显示，`markdown to image`、`markdown to png`、`markdown to pdf` 对应不同量级和竞争度；其中 PDF 意图明显更大，但竞争也更强。来源：`D:\code\Notes\projects\202607-MarkGleam\SEO-关键词与落地页研究.md`。
- **方法依据**：搜索结果、竞品定价、用户评论和社区提问分别回答“有人搜什么”“现有方案怎么做”“哪里不满意”“第一批人在哪里”，不应只看一个搜索量数字。

### 反证/限制条件

- 没有搜索量不代表没有需求，企业内部工具、强垂直工具和新任务可能主要靠社群、销售或口碑发现。
- 调研不能无限延长；如果首版成本只有一两个小时，轻量扫描后做原型可能比继续研究更划算。

### 来源风险

- Semrush 数据为第三方估算快照，不等于真实流量；正文只描述相对差异，并注明查询时间和估算性质。

## 论点二：MVP 要切成一个完整任务闭环，并尽快上线

### 支撑素材

- **案例**：MarkGleam 首版围绕“粘贴 Markdown—看到渲染—导出图片”闭环，大约一小时得到可用版本，随后部署到 GitHub Pages。来源：本次用户陈述；Codex 任务“构建免费无水印 Markdown 转图片工具”。
- **部署选择**：GitHub Pages 可以从仓库发布静态站点，并提供 `github.io` 默认地址；自定义域名可后续配置。来源：[About GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages)、[Configuring a custom domain for your GitHub Pages site](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site)。
- **后续成本证据**：代码仓库 2026-07-29 至 2026-07-31 的提交集中在 PDF 导出、移动端、浏览器兼容、域名、许可、语言和页面结构，说明“首版快”与“产品成熟”是两件事。来源：`D:\code\markdown-to-image` 的 Git 提交历史。

### 反证/限制条件

- 需要服务端计算、私有数据、账号权限或长任务队列的产品不适合只用 GitHub Pages。
- 首版也不能省掉任务闭环中的“结果能否带走”；只有预览、不能稳定导出，不算完成。

### 来源风险

- “大约一小时”是作者回忆，不是工时系统统计；正文必须限定为可用首版。

## 论点三：首批真实用户的失败样本比泛泛流量更有价值

### 支撑素材

- **案例**：工具发布到小红书后，有用户实际使用并反馈导出 PDF 是黑的，沟通后还提供原始文件。真实样本帮助定位了隐藏预览节点、透明画布和离屏截图等问题，后续补了跨浏览器测试。来源：本次用户陈述；Codex 任务“构建免费无水印 Markdown 转图片工具”和“md2img pdf 导出”。
- **过程证据**：修复不只判断“文件生成成功”，还实际渲染 PDF 检查页面，并在 Chromium、Firefox、WebKit 做回归。来源：相关 Codex 会话摘要和仓库提交。
- **方法**：反馈至少收集“用户想完成什么、输入样本、操作步骤、实际结果、期望结果、环境信息”，同时先取得用户同意并对内容脱敏。

### 反证/限制条件

- 一个用户能暴露严重问题，但不能证明需求规模或功能优先级。
- 原始文件可能包含隐私和机密，不能默认上传、长期保存或用于公开复现。

### 来源风险

- 不公开用户原始文件和具体内容，只描述问题类型与修复方法。

## 论点四：SEO 扩展要从意图和产品差异出发

### 支撑素材

- **案例**：MarkGleam 的初始语言是“Markdown 转图片”，关键词研究后发现 PDF 意图量级更大，又扩展到 Mermaid、公式、代码、README 等邻近任务；同义词没有全部拆成页面。来源：`SEO-关键词与落地页研究.md`。
- **页面边界**：只有输入模型、默认状态、编辑流程或输出形态真实不同，才创建独立 URL；格式同义词和平台名优先在同一页自然承接。来源：MarkGleam 内部研究结论。
- **官方边界**：Google 将为相似查询批量创建近重复页面、把用户导向相同结果的做法列入 doorway abuse 风险。来源：[Google Search spam policies — Doorway abuse](https://developers.google.com/search/docs/essentials/spam-policies#doorway-abuse)。
- **数据来源**：上线后可在 Search Console 的 Performance report 观察查询、页面、国家和设备维度。来源：[Performance report](https://support.google.com/webmasters/answer/7576553)。

### 反证/限制条件

- 搜索量大不等于适合做：竞争、意图匹配、产品能力和维护成本可能更关键。
- SEO 需要收录和观察周期；新站几天的数据不能用于下结论。

### 来源风险

- 不把关键词工具估算写成未来流量承诺，不把单站结论外推为通用规律。

## 论点五：变现方式应匹配价值和成本，支付排在信号之后

### 支撑素材

- **案例**：MarkGleam 当前选择“免费 Web 获客与传播—Pro 桌面版买断—出现持续服务需求后再做 Cloud/API 订阅”，原因是现有工具主要在本地运行，尚无同步、团队和云渲染等持续服务。来源：`D:\code\Notes\projects\202607-MarkGleam\商业化策略.md`。
- **判断框架**：
  - 一次性买断：低频但单次价值明确、持续服务器成本低；
  - 订阅：持续交付同步、存储、团队、API 或内容更新；
  - 按量计费：成本随调用或生成量增长；
  - 广告：需要大流量，且可能伤害工具体验和隐私承诺；
  - 免费：可用于传播、开源生态、获客或验证。
- **需求信号**：用户主动询问去署名、自定义品牌、批量、API、团队协作，比提前画一个价格页更接近真实付费意愿。

### 反证/限制条件

- 免费用户的功能请求不等于愿意付费；口头付费意向也不等于成交。
- 买断、订阅和开源之间存在许可、升级、维护和支持成本，不能只按竞品价格复制。

### 来源风险

- MarkGleam 的商业方案尚未上线验证，正文只能作为选择方法示例，不能写成已被证明的最优策略。
