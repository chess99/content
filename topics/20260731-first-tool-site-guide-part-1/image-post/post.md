# 图文正文

> 小红书与抖音图文共用正文；平台标题和话题见 `topic.md`。

我用 AI 大约一小时做出了 MarkGleam 的可用首版，后面两三天却一直在修 PDF 黑图、移动端、Safari 兼容、域名和 SEO。

这件事让我更确定：首版只是证明代码能跑，产品要证明陌生人也能把事情做完。

如果你也有一个工具站点子，建议按这个顺序来：

1. **先写问题卡**：谁在什么场景遇到问题？现在怎么解决？哪里难受？结果怎么带走？
2. **限时看市场**：花 30—60 分钟搜结果、竞品、差评和用户原话，别一上来查成行业报告。
3. **只保一条闭环**：输入 → 处理 → 检查 → 带走。登录、支付、后台、自定义域名先放进“不做清单”。
4. **尽快上线**：纯前端工具用 GitHub Pages 默认地址也能收第一批反馈。
5. **找真实用户交作业**：发布后，一位用户拿真实文件测试，发现 PDF 导出是黑图，还愿意提供原文件。一个可复现的失败样本，比“挺好用的”更能推动产品。
6. **再做关键词扩展**：同义词放在一页，只有输入、流程或输出真的不同，才新建页面。搜索量大也只是待验证机会，不是流量承诺。
7. **最后谈变现**：买断适合低频但价值明确的本地工具；订阅要有同步、团队、云渲染或 API 这类持续服务。用户问功能只是候选信号，还要继续验证付费意愿。

七天后先检查三件事：有没有一条真的跑通的任务路径，有没有真实用户样本，下一步有没有证据。

账号、支付和授权，我准备等真正做完后再写下篇。
