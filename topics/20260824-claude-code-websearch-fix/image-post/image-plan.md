# 图文方案

## 读者问题

Claude Code 配了火山引擎/DeepSeek 的自定义 API，WebSearch 和 WebFetch 全挂了，怎么把联网能力搞回来。

## 一句话结论

装 Exa MCP 一个命令就够，日常搜索和读网页都能用；难抓的页面再加 Firecrawl。

## 最少张数

4 张。

## 每张图任务

### 图 1：问题

- 任务：让读者一眼认领自己的处境
- 关系：症状 → 原因
- 视觉方向 A：终端截图风格，展示 WebSearch 返回 0 结果 + WebFetch 报错，旁边标注"自定义 API 端点"
- 视觉方向 B：流程图，`Claude Code → 自定义 API (火山引擎) → WebSearch ❌ / WebFetch ❌`
- 选择：A，截图风格更直接，读者秒认

### 图 2：为什么

- 任务：解释为什么自定义 API 下这两个工具不能用
- 关系：架构分层示意图
- 视觉方向 A：三层架构图，模型层（火山引擎 OK）→ 平台层（WebSearch/WebFetch 走 Anthropic 服务端 ❌）
- 视觉方向 B：对比表，官方 API vs 自定义 API 的能力差异
- 选择：A，层次关系更清晰

### 图 3：解决方案

- 任务：给出具体可操作的命令
- 关系：工具 → 场景 → 命令
- 视觉方向 A：三列对照表，Exa MCP（搜索+读网页）/ Firecrawl（JS动态站）/ Chrome MCP（浏览器交互）
- 视觉方向 B：终端命令卡片，直接展示 `claude mcp add` 命令
- 选择：A 为主 + B 的命令，因为读者需要知道什么时候用什么

### 图 4：最终效果

- 任务：展示装好后的效果，给读者一个"搞定了"的确认感
- 关系：改造前 vs 改造后
- 视觉方向 A：before/after 对比，左边空搜索结果，右边 Exa 正常返回
- 视觉方向 B：完整工具链示意图，标注"一个命令补回联网能力"
- 选择：A，对比最直观
