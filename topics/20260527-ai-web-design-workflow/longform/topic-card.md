# 选题卡：怎么让 AI 写出好看的网页

## 核心洞察（一句话）

AI 写网页不好看，通常不是模型不会写 CSS，而是你把它当成了代码生成器；真正有效的做法是先让 AI 帮你形成设计判断，再把判断压进可执行的约束里。

## 目标读者

正在用 Cursor、Claude Code、Codex 等 AI Coding 工具做个人项目、内部工具或产品原型的工程师。他们会写代码，但经常卡在“页面能用但不精致”：颜色像模板，布局像 demo，移动端交互粗糙，不知道怎么把审美要求讲给 agent。

## 核心论点（3-5条）

1. 好看的页面不是 prompt 里多写几个高级形容词，而是先讨论产品气质、信息层级、交互路径和视觉方向。
2. `brainstorming` 的价值在于把“我要一个好看的页面”拆成可以讨论、取舍、验证的设计问题。
3. `frontend-design` 提供的是审美约束：字体、配色、空间、动效、差异化方向，能明显减少默认 AI 味。
4. `ui-ux-pro-max` 的位置更接近产品设计师：检查路径是否顺手、状态是否完整、移动端是否真的可用，并补齐可访问性、触摸目标、响应式、导航和动效这些基础规则。
5. 这只是工程师友好的路线；另一条业界路径是先在 AI 设计平台里完成高保真设计，再把设计系统和组件约束带回代码。

## 推荐结构

1. 从 `read.cearl.cc` 的前后对比说起：AI 不是只能写“能跑”的页面。
2. 误区：把“好看”当成 CSS 问题。
3. 我的三段式工作流：先 brainstorm，再定视觉，再磨交互。
4. 为什么这套方法有效：把审美拆成 agent 能执行的约束。
5. 业界的另一条路线：Figma Make、Stitch、Lovable、Webflow 等 AI 设计平台。
6. 可复用的实践建议：素材、prompt、截图对比、移动端优先、人审。

## 潜在问题

- 读者可能质疑“这只是换了几个 skill，和 prompt engineering 有什么区别？”主笔需要强调 skill 的价值是长期化、结构化、可复用的工作流。
- 读者可能想要完整 prompt。可以给方法和部分示例，但不要把文章写成 prompt 模板合集。
- “好看”有主观性。文章应承认审美不是自动化指标，因此要用前后截图、移动端交互、具体 UI 细节来说明。
- 外部 AI 设计平台路线不能写成软广，应作为互补方案，并讲清设计到代码仍有断点。

## 渠道建议

- 技术深度版（博客/内部知识库）：适合。可以保留 skill 内容、代码库案例、外部工具调研和方法论。
- 轻量化版（公众号）：适合。需要更突出前后对比图和“三步工作流”，弱化工具细节。

## 选题结论

PASS。这个选题有个人实践、有可视化对比、有可复用方法，也能顺带讨论 2026 年 AI 设计工具路线。核心风险是写成工具清单，需要始终围绕“如何把模糊审美变成可执行约束”展开。
