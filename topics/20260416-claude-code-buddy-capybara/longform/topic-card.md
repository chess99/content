# 选题卡：用 Claude Code 逆向自己，14400 次枚举换来传说闪光卡皮巴拉

## 核心洞察（一句话）

Claude Code 的宠物外观由 userID 哈希决定，而 userID 可以被手动修改——Claude 自己逆向了自己的二进制，找到了算法，并在 0.04 秒内帮你刷出传说闪光卡皮巴拉。

## 核心论点（3-5条）

1. **漏洞存在于登录路径分叉**：用 CLAUDE_CODE_OAUTH_TOKEN 登录时，accountUuid 不写入 ~/.claude.json，此时 userID 字段可随意修改，宠物跟着变。用第三方 API 的用户本来就没有 accountUuid，更直接。

2. **AI 逆向 AI 本身，是这篇文章的灵魂**：把原理告诉 Claude，让它去 190MB 二进制里找 JS bundle、读压缩混淆代码——这个过程本身比结论更有意思。

3. **第一版脚本出错，Claude 自己设计实验修正**：FNV-1a vs Wyhash 哈希算法搞错，Claude 通过校准实验（而非猜测）发现并修正——这是一个值得单独讲清楚的诚实细节，让文章有可信度。

4. **完整脚本是本文的差异化**：大 V 原文只讲原理和思路，没有可运行代码。本文给完整脚本 + 算法细节，是实打实的增量。

5. **14400 次枚举，0.04 秒**：结果的数字感很强，适合做钩子。

## 潜在问题（读者可能质疑的点）

**Q1：这算"破解"吗？会不会违反使用条款？**
处理方式：提前说清楚——这只是改本地配置文件里的一个字段，不涉及服务器端数据篡改，宠物展示是纯本地渲染。风险极低，但读者自己判断。

**Q2：订阅用户能用吗？步骤更复杂？**
处理方式：两条路径分别说清楚，不要把操作步骤混在一起。订阅用户需要先用环境变量登录，额外一步，但不难。

**Q3："Claude 逆向自己"是真的吗，还是噱头？**
处理方式：诚实描述过程——作者把原理思路提供给了 Claude，Claude 做了实际的二进制分析和代码阅读工作。协作关系，不是"完全自主"，但 Claude 做了实质性的技术工作（找 bundle、读混淆代码、设计校准实验），这个叙述成立。

**Q4：第一版算法出错，是不是说明 Claude 不可靠？**
处理方式：反过来用——Claude 自己发现并修正了错误，这恰恰是诚实和有用的体现。如果遮掩这个细节反而显得假。

**Q5：14400 次枚举，会不会找不到想要的宠物？**
处理方式：说明枚举空间覆盖范围，以及"传说闪光卡皮巴拉"在枚举空间里的位置，给读者期望管理。
