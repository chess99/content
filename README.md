# Content

个人内容创作资产库。这里保存选题从立项、研究、起草到多渠道发布的完整产物；发布项目只保留最终副本。

## 组织方式

账号级品牌资产与具体发布主题分开保存：

```text
brand/                    # 账号定位、命名、Logo、设计规范和跨主题模板
topics/                   # 准备发布或已经发布的具体内容
```

每个主题使用一个带创建日期的目录：

```text
topics/
  YYYYMMDD-topic-slug/
    topic.md
    post.md
    images/
    shared/
    xiaohongshu/   # 仅在存在渠道差异时创建
    wechat/
    douyin/
    blog/
```

- 日期取首次立项日期，不随各渠道发布日期变化。
- 内部改造计划、账号策略和品牌资产不作为待发布主题，不放入 `topics/`。
- 多渠道完全共用的正文和图片只保存一份，优先放在主题根目录。
- `shared/` 保存跨渠道复用的研究、信源和原始素材。
- 渠道目录只在存在实质差异时创建，保存平台改写稿或专属素材。
- `topic.md` 记录主题定位、各渠道状态、发布日期和发布链接。
- 旧主题允许继续使用迁移前的扁平结构；再次编辑时再按需整理，不做无意义的批量改名。
- ZIP 等传输包不入库，需要时从源文件重新生成。

## 项目边界

- 本仓库是内容资产的唯一来源。
- `D:\code\content-workflows` 保存 skills、工具和创作流程，不保存具体选题资产。
- `D:\code\blog` 只保存 `blog.cearl.cc` 构建和发布所需的最终文章副本及图片。
- 发布到博客时，从主题的 `blog/` 目录复制最终稿和图片到 `D:\code\blog\source`，不要在两个仓库同时编辑。

## 大文件

Markdown、JSON、提示词和最终发布图片正常纳入 Git。大型原始视频、音频、模型文件和可再生成的临时文件默认忽略；确需版本管理时使用 Git LFS。
